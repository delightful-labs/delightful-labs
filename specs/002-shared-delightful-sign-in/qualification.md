# Qualification requirements

Status: **Not run.** These are acceptance requirements for a later approved implementation, not completed tests or authorization to add/run implementation tests. Source inspection is recorded in [research](research.md).

Use two consumers representing Finance and Clipper, independent browser origins/storage and different Jazz app IDs. Use private sentinel records and an unauthorized control identity. Record SDK/provider/registry versions, configuration, environment and real persistence/acceptance evidence for each result; redact credentials. No production user data is required.

| ID | Requirements / criteria | Required exercise and evidence |
| --- | --- | --- |
| Q-01 | FR-001–002, SC-001 | Authenticate the same external identity in both apps with fresh independent storage; inspect both authoritative app mappings. Revisit both in fresh sessions. No UUID equality assumption; verify each app's private sentinel is denied to the other app's unauthorized identity/context. Shared identity alone creates no cross-app grant. |
| Q-02 | FR-003–004, SC-002 | Link a populated local-first account. Confirm original account ID, record IDs, owners and policies before/after, on restart and after provider login on a fresh browser. Recover the original account using its existing phrase in the original app/environment. |
| Q-03 | FR-003, FR-005, SC-002–003 | Preassign external identity to B, then try linking A; also race two devices and repeat same-account linking. Capture authoritative outcomes and original account/data integrity. No automatic merge, reassignment or silent switch. Qualify actual SDK/registry errors without guessed codes. |
| Q-04 | FR-005, FR-007–009, SC-003 | Lose responses at local-first founding, link intent and link acceptance; restart/cancel/dispose at each point. Prove supported authoritative reconciliation, retained ownership and no blind replay. Distinguish linked-but-client-open-failed from unlinked. Block release if no supported reconciliation exists. |
| Q-05 | FR-006, SC-001, SC-004 | Use independent sites with storage/cookie isolation and third-party cookies blocked. Qualify supported provider sign-in and cancellation. Inspect callback destinations and URL/log/storage captures for sibling tokens, roots or phrases; none may cross app boundaries. |
| Q-06 | FR-008–009, SC-003–004 | Account A → B → A during token fetch, registry mutation and client opening; late callback after cancel; duplicate attachment/tab and provider account refresh. Verify one owner, generation invalidation, settled resource cleanup and zero stale admission. |
| Q-07 | FR-007–010, SC-003, SC-005 | Transition with locally pending writes, remotely rejected writes and unknown outcomes; include failed shutdown and offline restart. Preserve original operation/account correlation and recovery facts. Do not label generic promise completion durable or remote-accepted. |
| Q-08 | FR-010–011, SC-002–003 | Offline cold restart with retained eligible local session; provider outage, registry outage, JWKS outage and storage eviction separately. Confirm only qualified local capabilities continue; no replacement account or fabricated mapping/acceptance. |
| Q-09 | FR-008, FR-012, SC-005 | Exercise selected logout policy, stale signed-in provider notification, provider sign-out failure, offline logout and another open app/device. Record local/provider/other-app completion separately and require explicit re-entry where policy calls for it. |
| Q-10 | FR-011, FR-017, SC-002, SC-004–005 | Local-first phrase recovery before/after linking, external-only provider recovery, provider account loss and denied/expired credentials. Verify no unsupported phrase export, no secret persistence/diagnostics, and honest host/provider privacy disclosures. |
| Q-11 | FR-013–014, FR-018, SC-004 | Reject production credentials/configuration at dev/preview boundaries and vice versa. Exercise expired preview callbacks, unregistered/wildcard redirect origins, wrong issuer/audience, altered JWT, changed subject, expired token and key rotation. Dispose preview registrations and prove production identity unaffected. |
| Q-12 | FR-015–016, SC-004–005 | Review public capability surface and resource ownership against existing adapters; verify no duplicate registry/secret store/domain schemas. Qualify accessible/localizable intent, conflict, partial-failure and recovery interactions in both consumer contexts without changing app policy. |

Every capability claim needs passing evidence for its relevant rows. A static inspection or mocked adapter does not establish deployed registry enforcement, actual offline durability, browser support or provider compatibility. Implementation tests, browser qualification and consuming-app adoption require later user authorization under repository agreements.

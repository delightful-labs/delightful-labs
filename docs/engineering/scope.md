# Instruction scope and approvals

The workspace root AGENTS.md is the common entry point. Follow its task-based
links and every applicable local entry/active feature. Shared engineering guides
are authoritative for common practice; local files own domain/product rules,
SDK adapters and project qualification. No project constitution is global.

The user explicitly directed the stricter engineering rules to apply to all
projects on 2026-11-11. Common approval, type-safety, workflow ownership, worker,
copy, accessibility/test and dependency restrictions therefore use the strict
baseline, even where an old local entry was looser. A local file cannot silently
waive a shared gate. Different formatting tools or translation architectures are
not ranked by age/location; preserve those explicit boundaries pending review.

Current system/developer/user instructions and actual task-specific user approvals
retain their precedence. Authorization persists within scope and can supersede a
document's default gate. Do not ask again for an already authorized action, infer
approval from silence, or treat a broad feature request as approval for new copy,
dependencies, visual choices, publishing or destructive data operations.

Before implementation tests, the user must review/approve their implementation,
unless the user has explicitly authorized implementation and testing for the
active task. The ongoing monorepo migration has that session authorization from
2026-11-10 and subsequent scoped instructions. This is a record of existing user
authorization, not a permanent exemption for future work. Identify affected
checks and preserve applicable review/commit/merge/catalog/release gates.

Work on feature branches, one focused task/review cycle at a time. Keep batches
small and obtain authorization for larger/multiple-route changes. Do not commit,
merge, publish, change repository settings or cut over production without the
required user authorization. An authorized migration does not authorize data
reset, credential changes, deployment destinations or repository archival.

Local Finance and Local First constitutions remain domain/framework requirements.
Their money/tenancy/provider/backup rules are not imposed on unrelated products.
Website content/publication constraints and Clipper's account/capture/extension
contracts remain local. Review conflicts explicitly; preserve the stricter common
constraint and stop only the dependent work when incompatible requirements need
an actual decision. Record new exceptions with scope, rationale and user approval
in the same change; do not invent an exception merely to complete a task.

Shared Spec Kit skills/templates/helpers have one root owner. Run a skill/helper
from the target project or set SPECIFY_INIT_DIR to its absolute directory. Follow
that project's feature selector; never overwrite a sibling selector. UI's version
qualification remains in its docs rather than acquiring another app's feature.
Historical specs, source memories and qualification results remain traceable in
Git and the migration disposition ledger; they do not reopen completed phases.

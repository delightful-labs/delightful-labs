# W01: Finance ownership and parity inventory

Baseline: monorepo `main` at `670fb720e15b15a4b308408c92301bd29a943561`,
2026-11-13. This includes merged spec PR #22 and CI correction PR #23. The only
subsequent source change since the original research baseline is documentation
and the three CI branch filters; Finance's runtime code is unchanged.

This is the concrete inventory for [W01](worker-migration-tasks.md), not a new
implementation design or claim that the worker handoff has happened. Source
paths below are relative to `apps/finance` unless stated otherwise. Every row
identifies current ownership, intended ownership, scope/lifetime and a parity
flow to retain. See [reuse/extraction ownership](worker-foundation-reuse.md) for
shared library boundaries and [baseline evidence](worker-baseline.md) for checks,
timings, commands and limitations.

## Storage decision overlay (2026-11-13)

W01's source/baseline facts remain historical. The user subsequently selected a
worker-accessible IndexedDB AccountStore in Local First. The
[W03 design](worker-native-custody-design.md) now owns target storage/import and
transaction custody; table references to permanent Window account storage or
Web Lock extraction below are superseded. The user explicitly excluded legacy
identity migration, source cleanup and old-version compatibility code; preserve
stable app/profile binding for the new store only.
Broker construction/generation remains a separate native capability.

## Current and intended resource owners

Window currently owns the application/domain actor tree and SDK session. Jazz's
existing SharedWorker/Wasm/database work is a different boundary: it does not
make component queries, authorization, aggregation or app workflow coordination
worker-owned. The SimpleFIN HTTP worker and service worker have separate jobs.
The inactive Finance `runtime/worker` foundation is not a running application root.

## Library ownership and extraction constraints

Use current Local First session/recovery/workspace/form/operation/transaction/
backup contracts rather than rewriting them as Finance worker infrastructure.
R1/R2 move Clipper's native adapters into Local First; both consumers retain
their stricter capability admission. R3 shares receipt/native custody mechanisms
only after whole-worker crash safety is designed and qualified. R4 is a finite
worker job, not a financial commit-drain primitive. Clipper's library/article/
reader/extension protocols and Finance's queries/permissions/money/provider
policies remain in their apps.

The inventory does not authorize modifying unrelated UI, localization catalogs,
schemas, provider consent, storage identities or backend policy. The next design
review is W02's inactive bundle proof or W03's native custody design after the
W01 baseline gate is satisfied.
